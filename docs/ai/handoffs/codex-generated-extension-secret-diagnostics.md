# Handoff: generated extension secret diagnostics

## Changed and why

- Corrected the FreePBX 16 `fetchExtension` secret query shape and variable type.
- Added `create_with_generated_secret` so extension creation consumes the secret generated by
  FreePBX Quick Create and never performs the destructive immediate `updateExtension` sequence.
- Made ambiguous create outcomes fail closed without replaying the write or reading a possibly
  competing endpoint's secret.
- Added bounded, message-free GraphQL diagnostics with safe codes, paths, HTTP status, and a
  one-way message fingerprint.

## Validation

- `.venv/bin/python -m pytest -q`: 394 passed, 2 documented xpassed.
- Changed-file Ruff check and format check: passed.
- SDK-boundary reviewer: OK.
- Runtime-stability reviewer: OK.

## Risks and blockers

- The secret read is intentionally restricted to a confirmed successful create response. An
  ambiguous response requires manual reconciliation even when an exact extension is observed.
- No live vendor call was made.
